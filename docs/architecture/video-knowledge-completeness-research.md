# 长视频知识点完整提取与用户补漏方案

更新日期：2026-08-04

## 开源方案调研

本项目重点比较了四类开源方法：

- [Google LangExtract](https://github.com/google/langextract)：面向长文本的结构化抽取，支持分块、并行处理、多轮 extraction passes、精确原文定位和可视化核对。它最接近“尽可能完整枚举知识点”的目标。
- [HKUDS VideoRAG](https://github.com/HKUDS/VideoRAG)：使用图驱动知识索引、层级上下文编码和多模态检索理解超长视频，适合跨片段问答和定位，但本身不保证穷举全部复习知识点。
- [Microsoft GraphRAG](https://github.com/microsoft/graphrag)：从非结构化文本抽取实体、关系和社区摘要，适合全局主题理解，但索引成本较高，也不是面向复习卡片覆盖率设计。
- [RAPTOR](https://github.com/parthsarthi03/raptor)：递归聚类并摘要成树，适合长文的层级检索；摘要树能改善跨尺度理解，但不能单独证明所有知识点均被枚举。

## LangExtract 真实 A/B 与采用决策

项目已直接引入官方 `langextract==1.6.x` 作为实验依赖，不再只停留在“借鉴思路”。适配器使用 LangExtract 官方 OpenAI provider 接入同一复习模型端点，并启用中文 `UnicodeTokenizer`、长文分块、多轮 extraction passes 和原文字符定位；任何不能逐字回指原文或不能映射到真实 `evidenceId` 的候选都会被丢弃。

2026-08-04 在 Kafka 高性能陈述式课程和带 20 项目录的 Python 基础面经上完成真实 A/B。LangExtract 将两类平均金标召回率从 47.5% 提升到 95.0%，绝对提升 47.5 个百分点；但总 Token 成本达到当前方案的 3.05 倍，Python 长视频的原始 evidence 映射成功率只有 62.8%，过滤后近重复候选约 12.4%。完整设计、冻结金标、逐例指标和复现命令见 [复习 Knowledge Curator × LangExtract A/B 方案与结果](../testing/review-curator-langextract-ab-plan.md)。

上述 A/B 的原始结论仍然有效：LangExtract 没有通过成本和原始定位率门槛。2026-08-04 根据产品侧“完整性优先”的明确选择，生产链路改为受控启用，而不是把 A/B 结果改写成已通过。线上只消费能够逐字回指原文并映射到真实 `evidenceId` 的候选；未定位输出不会进入 Prompt 或卡片。默认 `REVIEW_LANGEXTRACT_ENABLED=true`，可在额度或供应商异常时关闭。

线上复习图现在执行：

```text
evidence 清洗
  → LangExtract Curator（完整资料分块、2 passes、每批最多 8 个并发请求）
  → 精确原文定位
  → 跨 pass 近重复过滤
  → 按 topic 轮询选择最多 32 个知识单元
  → gpt-5.6-terra 生成摘要与卡片
  → knowledgeUnitId 完整覆盖 + 问题/答案/evidence 门禁
  → FSRS 持久化
```

LangExtract 在一次生成任务中只运行一次，Repair 的后续 Terra 轮次复用同一候选上下文。默认每份资料最多 32 次 LangExtract 模型请求、单请求超时 120 秒；同一资料使用 8 个 worker，整个 Python 进程也通过共享闸门限制最多 8 个并发 LangExtract 请求，避免多份资料叠加后无界扩张。当前本机为 20 核/28 线程、15.78GB 内存，因此没有采用 10 个以上的默认并发。

线上仍采用以下已验证有效的约束：

1. 按视频时间或文档结构分块，先在每个局部块内执行高召回知识单元抽取。
2. 对长资料运行多轮抽取，使用不同关注维度发现定义、机制、流程、因果、对比和实践结论。
3. 每个候选必须绑定原始 evidence 和位置，不能只保留无来源摘要。
4. 最后执行跨块语义去重、覆盖审计和卡片质量门禁。

真实 A/B 已证明这比“先用正则找问号，再要求模型覆盖问题清单”更适合普通课程讲解。陈述式知识点不需要伪装成原始问题；正则只负责噪声过滤和确定性校验，知识候选由 LLM 从局部 evidence 中提取。当前生产启用是完整性优先下的显式权衡，仍需持续监控 Token 成本、定位过滤率、近重复率和人工补漏率。

## 本轮落地：用户可控补漏

用户已经知道遗漏主题时，不必重新运行整份资料生成。本轮增加一条独立链路：

```text
用户提示与最近对话
  → 当前文档 evidence 相关片段与相邻片段
  → 当前活动卡片去重基线
  → gpt-5.6-terra 提取补充候选
  → 问题、答案、evidence 忠实度门禁
  → 语义、来源键和永久排除记录去重
  → add-only 插入新卡片
```

该链路不调用整批 `save_generation`，因此不会执行“停用旧卡片并重建”的逻辑。它只插入通过门禁的新来源键，并更新资料的活动卡片计数；既有卡片字段和 FSRS 学习历史完全不变。

## 边界

- 用户提示是检索意图，不是事实来源；evidence 没有支持时返回零新增。
- 会话历史只帮助解析“它后面那个机制”等追问，不能跨资料引用事实。
- 新卡片立即到期，使用全新 FSRS 初始状态；旧卡片排程不受影响。
- 补漏是用户纠错通道，不等于自动覆盖率已经达到 100%。后续如实现自动多轮 Curator，应增加按块覆盖率、重复率和人工抽检评估。
