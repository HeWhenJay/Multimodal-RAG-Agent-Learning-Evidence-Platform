# 复习文件夹与结构化卡片保真设计

更新日期：2026-08-03

## 目标

复习中心需要同时满足两种不同的组织维度：FSRS 的“今天该复习什么”和用户自己的“这些资料属于哪个主题”。前者继续由到期时间与每日文档额度决定，后者通过用户文件夹组织，二者不能互相改写。

长视频或面经已经明确列出问题清单时，原始问题本身是高价值结构，不应再被普通资料的固定卡片上限压缩。系统仍由 DeepSeek 生成卡面文案，但选题范围必须优先继承资料已有结构。

## 数据边界

- `learning_review_folder` 保存用户自定义文件夹名称与时间戳。
- `learning_review_folder_material` 保存一份文档到一个文件夹的可选归属；`material_id` 唯一，保证文档不能同时出现在多个文件夹。
- 文件夹删除通过外键级联删除归属关系，原始 `learning_material`、`learning_review_material`、卡片与评分日志不受影响。
- 资料被永久移出复习中心时同步删除文件夹归属，避免空统计长期残留。

## 提炼流程

1. 对整份资料的 evidence 去重和噪声清洗，不先做 16 段截断。
2. 从原始 transcript/正文 evidence 中提取明确问句，忽略父段摘要、视频片段摘要和 OCR 转场。
3. 以命中问句的 evidence 及其相邻原文为优先输入，再补充首尾均匀采样，普通资料最多 16 段，结构化资料最多 48 段。
4. 原始问题不超过 8 个时维持普通的 3-8 张目标；超过 8 个时动态提高上限，最多 32 张，并要求逐项保留有明确答案的问题。
5. DeepSeek 一次返回摘要和全部卡片；服务端继续逐卡校验问题、答案、提示、来源问题和 evidence，不为凑数生成本地卡片。

## 一致性与并发

- 新建、重命名、删除文件夹和移动文档都校验当前认证用户。
- 批量移动先锁定目标文件夹与全部资料，任一资料无效则整次回滚。
- 文件夹归档会把文档从主页面资料列表、今日到期统计和资料队列隐藏，文件夹详情仍读取全部活动卡片；解除归档后恢复主页面展示。未归档资料的今日队列排序仍使用 `learning_review_material.display_order`，FSRS 仍只读取卡片与评分日志。
- Prompt 版本升级到 `review-card-v11` 后，既有资料通过当前索引版本与提炼器版本检查分批重新生成，同一稳定来源键继续继承历史 FSRS 状态；LangExtract 候选按 `knowledgeUnitId` 做完整覆盖审计，原始问题继续过滤无主题口语反问，Repair 保留上一版合格卡并只替换坏卡。

## 知识依据

设计采用用户笔记 `[[RAG相关/Pre-Retrieval预检索/索引优化/RAG中索引环节优化]]` 中“摘要必须与原文绑定”的原则，以及 `[[RAG相关/Pre-Retrieval预检索/索引优化/摘要索引-痛点分析]]` 中“摘要过短会丢失高价值结构”的提醒：视频问题清单作为原文结构参与选题，摘要只用于总览，不能代替完整问题集合。
