# 学习资料复习排程设计

更新日期：2026-08-01

## 主流方案调研

“艾宾浩斯遗忘曲线”描述了记忆随时间衰减的现象，但并不是一套可直接照抄的个人复习日历。工程实践主要分为三类：

| 方案 | 核心做法 | 优点 | 局限 |
| --- | --- | --- | --- |
| 固定间隔表 | 按 1、2、4、7、15、30 天等固定节点提醒 | 简单、透明 | 不利用用户实际回忆结果，所有知识点间隔相同 |
| SM-2 | 首次 1 天、第二次 6 天，之后按 Easiness Factor 递增；0-5 评分纠正难度 | 经典、易实现 | 模型较旧，只用单个难度因子近似记忆状态 |
| FSRS | 维护 Difficulty、Stability、Retrievability，按目标记忆率计算到期时间 | 个性化、可解释、能适应提前/延后复习 | 需要持久化每张卡片状态和真实评分历史 |

Anki 当前文档将 FSRS 作为旧 SM-2 的替代方案，并说明默认 `90%` 目标记忆率通常能平衡记忆效果与复习负担；目标越接近 `100%`，复习量会快速上升。Open Spaced Repetition 提供了 MIT 许可的 Python 实现 `py-fsrs`，支持四档评分、UTC 时间、卡片 JSON 序列化和状态恢复。本项目采用 `fsrs>=6.3.1,<7.0`，目标记忆率默认 `0.90`。

主要资料：

- [Anki Manual：FSRS 与目标记忆率](https://docs.ankiweb.net/deck-options.html#fsrs)
- [Open Spaced Repetition：FSRS 原理与实现列表](https://github.com/open-spaced-repetition/free-spaced-repetition-scheduler)
- [Py-FSRS 官方实现](https://github.com/open-spaced-repetition/py-fsrs)
- [SuperMemo：SM-2 原始算法](https://www.super-memory.com/english/ol/sm2.htm)

## 选择结论

本项目不是把固定间隔表命名为“艾宾浩斯算法”，而是采用能表达遗忘概率的 FSRS：

1. 每个关键知识点是一张独立卡片，各自拥有 FSRS 状态。
2. 用户必须先主动回忆，再揭示答案并选择忘记、困难、记得或轻松。
3. 后端根据评分更新稳定性与难度，并计算 `dueAt`。
4. 复习提醒只由持久化 `dueAt` 驱动；前端只展示，不复制排程算法。
5. 新用户使用通用 FSRS 参数；积累足够复习日志后可再加入个人参数优化，当前阶段不提前做不可靠拟合。

## 内容生成流程

```text
READY/PARTIAL 学习资料
  -> 按 indexRequestVersion 幂等扫描
  -> 获取可选 Redis 生成短锁（多实例并发去重）
  -> 使用标题、摘要和 RAG evidence 判断是否为学习型内容
  -> 一次 LLM 调用从 evidence 提炼 3-8 张关键知识点卡片
  -> 校验每张卡片引用的 evidenceId 必须真实存在
  -> 保存卡片正文、来源、视频时间段和 FSRS 初始状态
  -> dueAt 到期后进入提醒队列
```

学习型内容的正向特征包括八股、面经、课程、教程、知识点、原理、机制、实践总结、技术讲解以及结构化问答；简历、JD、系统日志、上传清单等业务材料默认不生成复习卡片。模型只能在提供的 evidence 中提炼，不得补写资料中没有的事实。

## 关键不变量

- 复习正文是 `question + concise answer`，不能把原视频 URL 当答案，也不能提示用户“重新观看完整视频”。
- 时间码、页码编号和重复字幕不能作为问题主体；模型结果与本地降级都必须在持久化前过滤此类噪声。
- `evidenceRefs` 至少包含一条真实来源；没有 evidence 时不创建卡片。
- 视频引用保留时间段，文本引用保留章节/页码/幻灯片/sheet 等已有字段。
- 资料重建索引时仅当 evidence 标识和规范化知识内容指纹都一致才保留排程状态；内容变化时创建新身份，避免不同知识点错误继承旧进度。
- 评分日志不可覆盖，后续可用于 FSRS 参数优化和学习效果分析。
- 所有数据库查询同时约束 `user_id`，不能依赖前端传入的所有者字段。
- 每个资料索引版本只允许一次模型请求；Redis 不可用时退化为进程内短锁，原子解锁失败时等待 TTL，PostgreSQL 版本幂等仍负责最终一致性。
- Python 多实例启动时先获取 PostgreSQL advisory transaction lock，再检查并执行增量迁移，避免并发 DDL 和重复写入迁移版本。
- Prompt 版本与模板集中在 `ai-python/prompts/`，evidence 被视为不可信输入，模型必须忽略其中的指令文本。
- 每日接口先按用户保存的资料优先级和文档额度选择 group，再返回入选资料的全部到期卡片；同一资料当天只占用一次额度，列表不返回答案，揭示接口再次校验卡片归属。

## 提醒边界

当前版本提供持久化到期队列、顶部到期数量、复习中心和用户主动授权后的浏览器通知。浏览器关闭后的系统级推送需要 Web Push、邮件或移动端推送基础设施，不在本次仓库已有能力范围内；后续接入时仍应直接消费同一 `dueAt`，不能另建一套间隔规则。
